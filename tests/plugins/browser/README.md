# 浏览器交互验收

运行 `pnpm dev --host 127.0.0.1 --port 5173`，打开
`http://127.0.0.1:5173/tests/plugins/browser/index.html`。
建议使用独立浏览器测试配置或独立端口；夹具使用该 origin 的真实 IndexedDB、文档与设置，不清空已有数据。

这是手动交互夹具，不是自动化通过标记。它加载真实 App，测试插件经 ZIP/parser/consent/Blob 加载链路运行，React 从宿主共享。只有页面底部的测试控制台可以直接驱动宿主事件；插件本体不导入宿主内部模块。测试入口位于 `tests/`，不进入生产构建。修改夹具或宿主代码后完整刷新页面，再开始下一轮验收。

## 当前导航预期

产品入口是 **编辑 → 首选项 → 常规 → 管理插件**，管理器中再选择“可用插件 / 已安装 / 插件设置”。

“插件设置”包含商店提供者、离线开关和开发目录加载。SDK 的 `settings-view` 是另一种插件贡献：当前源码将其作为动态首选项标签。控制台“打开贡献视图（端口验收）”只测试这一端口，不作为插件管理器的产品导航预期。

## 可重复执行的场景

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 安装与授权 | 控制台“安装验收 ZIP”，先拒绝，再重新安装并授权 | 拒绝不激活；授权后管理器“已安装”显示“浏览器验收插件”、本地导入和摘要 |
| 菜单与共享 React | 工具 → 浏览器验收：打开对话框 | Hook 组件正常渲染，显示项目文件名，无 invalid hook call |
| 选择订阅 | 对话框或贡献设置视图内按 Ctrl+Alt+S | 选择显示 `browser-selection`；关闭视图释放组件订阅 |
| KV 与重启 | 保存计数，关闭后重新打开，再刷新页面重开 | 计数保持；插件从持久安装恢复 |
| 网络 | 视图中“请求本地夹具”；再经管理器“插件设置”启用离线并重试 | 在线 HTTP 200；离线 `network-unavailable`，日志表明请求在端口被拒绝；离线状态跨刷新保留 |
| 表单与事务 | 工具 → 浏览器验收：元数据事务，填写标题并应用；控制台读取文档后撤销再读 | title metadata 更新；一次撤销恢复原文档。此操作替换测试文档的元数据，应在空白测试项目或已授权的样本上执行，测试后撤销且不保存覆盖源文件 |
| 动态贡献 | 启用插件后打开贡献视图，按 Ctrl+Alt+D | 设置贡献消失并回退常规；无需刷新。重新启用后重新出现 |
| 对话框清理 | 打开插件对话框后按 Ctrl+Alt+D | 对话框随 scope dispose 自动关闭，菜单命令消失 |
| 管理器启停 | 常规 → 管理插件 → 已安装，关闭插件开关并刷新 | 禁用状态保持；重新启用恢复菜单与视图 |
| dev 来源 | 启用插件后控制台“加载 dev 副本”，确认开发授权 | 管理器显示“开发目录”；授权说明覆盖本会话源码修改；刷新恢复原本的本地安装副本 |
| 卸载 | 管理器卸载测试插件并刷新 | 安装条目、菜单与设置贡献不再出现；出厂 time-shift 表单仍可打开 |

首次初始化尚未结束时不要立即刷新；等待出厂插件和测试插件稳定后继续，避免将主动刷新计为启动崩溃。结束后卸载 `test.browser-migration`，恢复离线开关，撤销测试文档事务。
