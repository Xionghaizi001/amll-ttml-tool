# 作用域内局部覆盖验收

2026-10-20：当前交付范围通过。环境为 Windows、真实 Chromium、Vite 生产编译的完整宿主；使用独立 localhost 来源，走真实 Blob 加载、许可对话框、IndexedDB 安装存储和插件管理器。

## 真实 UI 回归

临时目标 `accept.target` 声明命令、标题栏动作和字符串表，经公开 SDK 注册实际行为。命令打开带必填文本字段的 `ui.showForm`，提交后写入插件 KV 并通知结果；表单标题、字段、提交按钮与通知均在调用时通过 `host.i18n.t` 读取。

两个临时功能包 `accept.pack.a` / `accept.pack.b` 均依赖目标 `^1.0.0`，各自提供 localization 和 icons 资源，替换 6 处文案和 1 处图标。资源额外携带 id、handler、capabilities、activationEvents 与不存在的字符串地址，检查运行时过滤边界。三个包均按普通 JSON 包安装并经过真实许可入口。

| 场景 | 验收结果 |
| --- | --- |
| 无覆盖基线 | 工具菜单为“基础命令”，表单标题/字段/按钮使用基础文案；必填字段为空时提交禁用，填写后原处理器写入 KV 并通知 `基础结果 baseline` |
| 安装 A | 菜单变为“A 命令”；表单标题、字段、提交按钮及通知同步切换；提交 `after-A` 后 KV 为同一值 |
| 安装 B | 受保护的“覆盖冲突”弹窗报告目标、胜者、败者和 7 处冲突；检查 `data-amll-protected` 存在 |
| 弹窗停用胜者 | 停用 B 后菜单即时回退为“A 命令” |
| 全部禁用 | 禁用 A 后菜单与重新打开的表单全部恢复基础文案 |
| 保留胜者 | 重新启用 A、B，继续使用 B 后菜单、表单和通知使用 B 文案；提交 `after-B` 后 KV 为同一值 |
| 覆盖链 | 管理器目标条目显示“已被 语言包 A/B 覆盖”、包 id、localization/icons、本地导入来源；A → B 顺序及“7 处被 B 取代”正确 |
| 管理器启停 | 管理器禁用 B 后仅保留 A 的来源；重新启用 B 再次提醒，允许保留 |
| 重启恢复 | 页面刷新后 B 仍胜出，不重复提醒旧冲突，已安装包和 KV 保留 |
| 反转启用顺序 | 禁用并重新启用 A 后弹窗明确 A 胜出；保留并刷新后仍为“A 命令”，管理器链变为 B → A |
| 标题栏消费 | A 胜出时实际 SVG 为 Stop 图形，键盘聚焦后的 tooltip 为“A 动作 · accept.target” |
| 行为边界 | 原命令 id 仍存在，不产生 `hijack` 命令；原处理器与字段 key 保持，能力和激活事件不变；5 类非法/未知地址均含覆盖方、目标与 entry 的诊断 |
| 卸载回退与清理 | 管理器卸载胜者 A 后回退 B，再卸载 B 后清除覆盖信息、菜单恢复基础文案；最后卸载目标，列表不再包含验收插件 |

验收修复：冲突发生在覆盖注册阶段，早于胜者进入运行实例列表。原弹窗只订阅冲突队列，因而首次加载的胜者一直显示插件 id。`OverrideConflictDialog` 现订阅胜者实例变化，加载完成后刷新名称；在重新编译并启用新版 PWA 后实测名称正确。

临时源码入口与插件在验收后移除，未加入 factory lock、catalog 或生产入口。临时生产构建的删除被自动审批策略拒绝（工具仅返回 blocked by policy），构建与截图保留在 Git 忽略的 release/，预览进程已停止。本次未增加依赖，也未改变覆盖协议或插件业务行为。

顺序修复：最终全量复跑发现同一毫秒的启用会保存相同 enabledAt，重启后胜者可能由加载顺序决定。共享加载器现以已观察到的最大启用值为基准严格递增新值，恢复时保留旧值；固定时钟及回拨时钟两组测试覆盖首次激活、重新启用、逆序恢复和恢复后的再次启用。开发模式的会话状态也同步最新启用值，并增加开发语言包重新启用后胜出的回归用例。

## 尚未交付或未实测的边界

- 主题包 overrides 注册、`settings` 声明式表单渲染及 `/settings/...` 运行时消费仍随真实消费者落地。本次表单验证覆盖的是字符串表消费路径，不能据此宣称 settings 渲染器已交付。
- `ui.showForm` 接收打开时的文案快照，临时表单没有 `/settings/...` 覆盖地址。已经打开的表单不会因覆盖增减自动重建；插件动态视图需监听 `host.i18n.onLocaleChanged` 后重读字符串。
- 目标升级后需重新启用覆盖方，才会按新 manifest 重新过滤。旧版本已保存的相同 enabledAt 缺乏历史先后信息，仍以注册顺序打破平局；重新启用需要优先的覆盖方后即可固定顺序。
- 本次 JSON 包走真实 UI；ZIP、locale 合并/回退、格式标题、激活失败撤销及持久化异常由合同测试覆盖。
- macOS/Linux WebView 与 Tauri 桌面生产包未在本次实测，仍属正式平台验收。
